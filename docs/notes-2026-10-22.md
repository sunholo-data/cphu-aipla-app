## The day in one page

- **Students did not know what to do.** There was no scaffolding, introduction or
  walkthrough, and *everyone's first question was "What do I do?"* This is the
  headline.
- **Should the tutor carry that, or the teacher?** The tutor should introduce itself
  and be more proactive, but there is a tension with teacher agency. Should
  teachers design the introduction into the activity? How do we equip teachers to
  introduce the AI tutor well?
- **Maths quality:** possible maths errors, and **the tutor did not use equations**.
  It answered physics in heavy prose where an equation would have done the work
  (clarified by M, 2026-10-22: rendering was not the problem). Decided: **build a
  verifiable maths/calculator tool**, so the tutor computes with a tool rather
  than from its training. We also need to check whether a maths tool exists and is
  being called, and to surface tool usage in the logs.
- **Pacing:** the stream is so fast that it arrives as one big blob, graphs move too
  fast, and there are too many notifications. There is a consensus for *smarter, not
  faster*.
- **The kettle sim sends the AI too many settings**, and the sim class report
  missed things: power (W) was reported but time was not, and "parameters explored"
  was incomplete.
- **Liked:** tutor personalities / frameworks.
- **Schedule moved up:** we want to collect data **now**, but the **Google DPA is
  blocking**. So: prioritise local running off Google Cloud, and ask legal about EU
  cloud options. (SkoleGPT uses Danish library-centre servers.)
- Research calendar: school visit in **November** (epistemic orientation, 5–10
  students); teacher training around **Christmas / January**; teaching in the
  platform in **March**; reflection in **April**.

**Found while writing them:**

- **No log records which tools a turn called.** Events with no text are skipped
  before logging, and the TTFT `tools_invoked_count` counts only tools called
  before the first token. That figure has always undercounted, so any earlier
  analysis that read it as a tool count is wrong in the same direction (1.1.152).
- **Class insights' "sim runs" most likely read 0 for every sim.** They filter on
  `tool='sim_run'`, which no current writer emits (1.1.155).
- **In a teacher-built activity the tutor never reacts to the sim.**
  `concept-dialogue` opts in to the greeting but not to `proactiveEventReactive`
  (1.1.154).
- **`LOCAL_MODE` is not off Google.** It still calls Gemini and writes no research
  record (1.1.158).

**Not designed:** the written manual (the guides already print as PDFs, so ask
teachers what they need first), the training and teaching schedule, and the research
items (epistemic orientation, steering vectors, the Infomap cluster map, whole-class
discussion). These are planning and research questions, not defects to fix.
