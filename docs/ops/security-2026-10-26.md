# Security backport review — 2026-10-26

## Final CA trust-store follow-up

The dependency scan did not cover gRPC's embedded trust store. Certifi
2026.10.19 still retained the C1/C3 roots, while gRPC's bundled roots also
retained G3. Update both backend and CLI to **Certifi 2026.10.23** and use that
curated bundle for Python HTTP and gRPC defaults. The published distrust list
is **G3, C1 and C3**; G1 remains trusted. See the
[authoritative CA change](https://github.com/certifi/python-certifi/commit/b60466c9f2882d9cf088943c650b0faac06c080c).

`config.tls` configures `SSL_CERT_FILE`, `SSL_CERT_DIR`, `REQUESTS_CA_BUNDLE`
and `GRPC_DEFAULT_SSL_ROOTS_FILE_PATH` before client initialization. Docker
also sets them before any Python import. The CA directory points at Certifi's
package directory rather than the system store: OpenSSL can lazily reload a
removed root from its default hashed directory even with a clean CA file.
Explicit operator overrides remain authoritative.

Tests inspect real OpenSSL roots and its directory fallback, and check all
three removed certificate fingerprints. Real Google HTTPS and gRPC TLS
handshakes pass without credentials or application data. The first dev image
also uses verified Node **22.23.4** from base digest
`sha256:fe4f6d74e20370acb04ad889077d14d0f64a9c8ea6a42bc60cddf1e844699914`,
including its bundled Undici and CA fixes.

**The earlier backend image `4888e2e2…` below is first-phase evidence, not the
final release candidate: the CA follow-up must be included before promotion.**

## Compatible Zod 3 backport

A2UI 0.10.x uses Zod 3's `_def.typeName` and related introspection APIs.
Even A2UI 0.14.0 still requires Zod 3. Forcing Zod 4 across those consumers
would silently break component binding. There is no published Zod 3 patch.

`frontend/scripts/patch-legacy-zod.mjs` ports the fail-before-element-walk
behavior from [upstream e06a510](https://github.com/colinhacks/zod/commit/e06a510b6fc1e6e28e3201fd116ca2a76212f6be)
to Zod 3's bounded arrays and sets. Zod 3 maps have no size-check API.
Because the upstream Zod 4 fix leaves unbounded schemas unchanged, this
backport also checks public validation inputs before sync, async and
Standard Schema validation: at most **10,000 values**, **64 levels**, and
**2,097,152 aggregate string/key characters**. Oversized input returns one
validation issue; it is never silently truncated. Inputs exceeding these
limits are an intentional compatibility boundary to review against real
workloads. Trusted schema transforms remain application code, not an input
sandbox.

The patch covers every locked Zod 3 copy and the v3 compatibility entry point
bundled in Zod 4, in both ESM and CommonJS. It preserves Zod 3's public and
introspection APIs. Source and patched-output SHA-256 values are committed;
unknown versions, altered source or a missing copy fail installation.
`npm ci` applies the backport through `postinstall`, including in Docker.

Raw `npm audit` still reports the legacy version. The security gate prints
that report, installs the frozen production dependency tree into an isolated
temporary directory, verifies every patched byte and runs **38 runtime
checks**. Only then can this one advisory and chains attributable solely to
it be reported as **BACKPORTED**. Another advisory, an unexpected copy or a
missing build hook still blocks. Seven gate tests cover those failure modes,
including actual scanner failure under macOS Bash. This is source-verified
remediation, not a blanket or time-limited advisory dismissal.

## OpenTelemetry without promoting ADK 2

ADK 1 imports the Events API removed by newer OpenTelemetry SDK releases.
`backend/scripts/backport_otel_tracestate.py` ports the parser fix from
[upstream d5224bf](https://github.com/open-telemetry/opentelemetry-python/commit/d5224bf4ffdf2aee1b592ad238dcc32ca957f26b)
onto exactly API 1.38.0: linear comma splitting, trimmed optional whitespace,
and the combined 8,192-character header limit before parsing. Normal
`traceparent` and valid vendor state are preserved.

The image build applies this exact-source patch. Container startup verifies
its hashes before starting the application. Replacements are atomic, so
uv's hard-linked wheel cache and other environments cannot be modified.
The audit permits this one CVE only after an isolated 1.38.0 installation
passes source-hash, build/startup-wiring and real-parser deadline checks.
Other OTel versions cannot use that legacy proof. On modern dev's 1.45.1,
the helper performs no source modification.
